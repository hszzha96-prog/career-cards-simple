# 更新与同步

## 一次普通更新

1. 在 `data/cards.json` 找到对应岗位，修改经过核对的内容。
2. 在 `data/evidence.json` 的同一 `page_id` 下补充来源、实际核验日期和待核事项。旧来源仍有用时保留。
3. 只有实际核验了新的材料，才更新 `data/project.json` 的 `snapshot_date`；纯代码补丁只更新 `version` 和 `CHANGELOG.md`，不伪造核验日期。
4. 执行 `python3 scripts/build.py`（同时更新 `dashboard/` 看板）。
5. 打开 `site/index.html` 和受影响岗位，检查宽屏、手机宽度、勾选与重开后的进度。
6. 检查版本差异，将数据、模板、脚本、`site/`、`dist/` 和变更说明一并提交到私有仓库。用清楚的说明，例如“补充小米岗位证据”或“修复目录跳转”。

构建会更新生成目录和当前 ZIP；`releases/岗位卡_简洁版_2026-11-25.zip` 为历史原件，保持不变。代码补丁可采用 `0.1.1`，新增卡或功能可采用 `0.2.0`。

## 增加岗位

以现有同类型卡片为字段样例，不沿用其中的经历结论或分数。先有清晰的岗位身份和原卡地址，再新增一条 `cards` 和一条 `evidence`。未知字段写“待核”；岗位不明时使用 `incomplete` 类别和证据核对清单。

三个身份字段须稳定：

- `page_id`：原岗位卡 ID，一岗一条。
- `filename`：仅小写英文字母、数字与短横线，以 `.html` 结尾，例如 `company-pageprefix.html`。
- `storage_key`：本浏览器进度键，建议 `career-simple-原page_id-prep-v1`；不同岗位必须不同，旧岗位不要随版本更换。

`cards` 与 `evidence` 的 `page_id`、`filename`、`category` 必须对应。`cards` 固定保留 4 项概览、5 项雇主条件、5 项个人条件、5 个能力维度、2 组项目证据、4 个下一步和 5 个准备项。证据不足就明确标注，不为了填满而编造。

分类值为 `candidate`、`applied`、`incomplete`、`closed`、`trash`。目录数量自动生成。改变分类必须有明确依据；准备清单的勾选不改变分类。

## 岗位小镇看板

新增岗位时，另在 `data/dashboard.json` 为它选一个像素图标和底色；不写会用默认图标并在构建时提示。看板读取同一份 `cards.json` / `evidence.json`，分类与数量自动更新。详见 `dashboard/README.md`。

## 模板与小米样板

`templates/simple.css` 与 `templates/checklist.js` 是公共视觉与交互来源。当前小米页另保留已确认的 HTML 快照，确保第一版与用户看到的一致。其数据、日期、调度台或公共模板变化时，生成器会重新渲染，沿用原来的进度键，不会静默忽略数据修改。

若要改变五项准备题的含义，先确认是否需要迁移旧勾选；仅保留键不保证旧勾选与新题含义对应。常规文案修改不要重置进度键。

## 原岗位卡与调度台同步

当前版本历史同步摘要在 `sync/2026-11-25-pages-receipt.json`，记录各原卡附件的引用和 SHA256。它是一次已完成上传的记录，不能作为未来版本已同步的证明。

构建仅准备：

- `dist/pages/`：每岗单独上传用的 HTML，返回目录的入口改为原调度台，避免单文件附件缺少相邻文件。
- `dist/pages/index.html`：在线目录，跳转至各原岗位卡。
- `dist/sync-plan.json`：相对已保存回执的 `new` / `updated` / `unchanged` 列表。

后续要同步时，先读原卡，确认身份和最新状态；上传对应附件后，只更新其简洁版入口。原文字、正式状态、勾选、结束/废纸篓记录都要保留。调度台更新 ZIP、在线目录及相关直达链接。最后逐页回读并比对附件 SHA256，再保存新的带日期回执。不要仅因本地生成成功就标“已同步”。

这份仓库没有定时任务、邮箱监控、自动投递或发信功能，也不自带跨服务凭据。GitHub 更新与 Pages 更新是两个独立动作。

## 未来公开版本

当前保留个人真实岗位资料，只用于私有仓库。若以后决定开源，从单独的通用模板项目开始，用明确标注的示例数据替换个人分析，移除私人 Pages、邮箱/云盘入口、同步回执、历史成品和 ZIP，再选择许可。不要直接将当前含历史记录的仓库改为公开。
